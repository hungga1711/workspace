# infra/ — guide for agents

```
infra/
  local/          docker-compose.yml for development + configs it mounts
                  (postgres init: roles, one database; optional pgbouncer profile,
                   livekit, seaweedfs s3)
  production/     docker-compose.yml (one image; postgres, app = web + server, caddy), caddy/ (reverse proxy with
                  automatic HTTPS: Caddyfile, run.sh), .env.example, entrypoint.sh (command → what runs),
                  web-config.mjs (runtime URLs + CSP), install.sh, backup.sh, restore.sh, upgrade.sh,
                  load-secrets.sh (secrets generated by the `init` job, for containers outside the image)
  templates/      one-click templates (plain compose without bind mounts, Coolify, Portainer, Railway, Unraid,
                  CasaOS) and the Caddyfile, which the image ships for them
  docker/         Dockerfile — one image (Alpine + its Node 22): esbuild bundles of the server and tools
                  (tooling/scripts/bundle-backend.mjs), the migrator and the web app
```

- Files: `STORAGE_DRIVER=local` (default in production without `S3_ENDPOINT`) keeps them in the `data` volume; the
  server serves the signed `/storage/<token>` URLs (Caddy routes them on the app domain). `/files/<id>` belongs to
  the web app (stable links inside documents), so never route that to the server.
- A change to the production compose usually needs the same change in `infra/templates/docker-compose.yml`
  (and its Coolify/CasaOS copies).

## Rules

- **Paths inside the image mirror the repo** (`/app/backend/server/dist/main.js` is the server's bundle,
  `/app/backend/server/migrations/`, `/app/infra/production/entrypoint.sh`). When you add a module or a runtime entry
  point, update `infra/docker/Dockerfile`, `tooling/scripts/bundle-backend.mjs`, `infra/production/entrypoint.sh`,
  `tooling/scripts/dev-server.mjs` and `tooling/scripts/migrate-all.mjs` together.
- **Bundling**: a new backend dependency is bundled into the server file unless it is listed in `EXTERNAL`
  in `tooling/scripts/bundle-backend.mjs`. List it there when it loads optional parts at run time, when it keeps global
  state shared with another external package (NestJS, rxjs), or when it is a native addon.
- **Caddy** sites live in `infra/production/caddy/Caddyfile` (`caddy/run.sh` turns the domain settings into their
  addresses) and `infra/templates/Caddyfile` (plain HTTP behind a platform's proxy); keep their routing in step.
  Security headers come from the web app, not Caddy.
- Build from the repo root: `docker build -f infra/docker/Dockerfile -t workspace .`
- Production secrets come from `infra/production/.env`; any left empty are generated once by the `init` job
  (`entrypoint.sh init-secrets`, read back by `load-secrets.sh`). Never hard-code a secret; document new variables
  in `infra/production/.env.example` and the root `.env.example`.
- Local compose is for development only (dev passwords).
- No Valkey or Redis: events, caches and Socket.IO fan-out live in the server process (ADR-0021), so the production
  stack runs one `app` container, never two replicas of it.
- Docker disk on developer machines is small: tests upload to the `workspace-test` bucket; don't add volumes that
  grow without bound, and don't prune other projects' images or volumes.

## Commands

```bash
pnpm infra:up | pnpm infra:down                 # local stack
pnpm migrate                                    # every module's schema
cd infra/production && docker compose build && docker compose up -d   # see its README
```
